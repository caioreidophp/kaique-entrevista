# Admissions Screenshot Checklist

Screenshots should prove that the project is real, useful, and safe to show. Use only synthetic demo data.

## Screenshot Set

Capture these screens after checking that no private data appears:

- Home page with module cards.
- Freight dashboard or Central Analytics with period/unit filters.
- Freight list or SPOT/displacement workflow.
- Payroll dashboard, payment list, or daily pay/extras screen.
- Recruitment/interview screen with candidate status and PDF/attachment area.
- Vacation timeline or vacation dashboard.
- Registry screen showing collaborators only if the demo data is fully synthetic.
- Activity log or permissions screen, if safe to show.
- README or documentation page showing architecture/case study links.

## What Good Screenshots Should Show

- Real workflow density, not empty pages.
- Filters, statuses, and actions.
- Synthetic names and data that look believable.
- No real phone numbers, emails, CPF/RG/CNH, addresses, or private files.
- Browser zoom at 100%.
- A clean browser with unrelated tabs hidden if possible.

## What To Avoid

- Screens with blank tables.
- Screens with broken accents or encoding problems.
- Screens showing `.env`, database files, storage paths, or logs with secrets.
- Screens showing real company documents.
- Screens that require a long explanation to understand.

## File Naming

Use simple names:

- `01-home.png`
- `02-freight-dashboard.png`
- `03-payroll-pending-extras.png`
- `04-recruitment-interview.png`
- `05-vacation-timeline.png`
- `06-architecture-docs.png`

## Final Review

Before adding screenshots to GitHub or an application:

- Ask: "Could this expose a real person or company record?"
- Ask: "Does this screenshot show something I actually built?"
- Ask: "Would a reviewer understand the purpose in five seconds?"
